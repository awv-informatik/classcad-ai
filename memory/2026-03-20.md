# 2026-03-20 — Training Session Notes

## Renderer Fix: Per-Body Coloring

- Added per-body color palettes to `scripts/render-direct.mjs` — 8 distinct colors cycling per container (blue, orange, green, pink, olive, teal, purple, gold).
- **Bug found:** `getLastGraphic()` returned intermediate/stale graphic data from API responses (e.g., `boolean()` response contained old containers + new merged container). This caused the renderer to assign different colors to what should be a single merged body → visual patchwork.
- **Fix:** Flipped priority in `renderSession()` — always call `v1.common.recalc` first to get the true current container state. Fall back to cached graphic only if recalc fails. Applied to both solids and curves rendering paths.
- Verified: 3 bodies → 3 colors, after union of 2 → 2 colors, after full union → 1 uniform color.

## HOW-TO-TRAIN.md Rewrite

Major restructure to fix the pipeline clarity. Key changes:
- **Pipeline stated upfront:** "Read → Script → Run → Journal → Apply to skill files → changes.md"
- **Explicit completion gate:** Session is done when `changes.md` exists with diff OR journal has `## Skill Updates` section explaining why no changes needed. No third option.
- **📌 Skill update flags:** During journaling (Step 3c), mark findings with `📌 Skill update:` as a TODO list for Step 4.
- **Step 4 and Step 5 are separate:** Updating skill files (Step 4) and recording the diff (Step 5) are distinct actions.
- **"Nothing new" requires justification** — silence is not an option.
- **Snapshot design rule:** Create geometry with asymmetric offsets, different sizes. Before/after comparison is mandatory — if snapshots look identical, write another script with better geometry.
